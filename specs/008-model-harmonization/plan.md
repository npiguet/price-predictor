# Implementation Plan: Model Harmonization

**Branch**: `008-model-harmonization` | **Date**: 2026-03-15 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/008-model-harmonization/spec.md`

## Summary

Collapse six CLI commands (`train`, `train-transformer`, `predict`, `eval`, `evaluate`, `evaluate-transformer`) into three unified commands (`train {model}`, `predict {model}`, `evaluate {model}`). Standardize all pipelines on the converted card text format from `./output/`. Organize model artifacts into `./models/<model>/` subdirectories. Update the REST API to accept converted card text instead of Forge scripts.

The primary new component is a converted-card-text parser that produces `Card` entities for the sklearn feature engineering pipeline. The transformer pipeline already consumes raw text and needs no parser.

## Technical Context

**Language/Version**: Python 3.14+
**Primary Dependencies**: scikit-learn, pandas, numpy, joblib, PyTorch, transformers (BERT tokenizer), FastAPI, uvicorn
**Storage**: `.joblib` model files in `models/sklearn/`, `.pt` model files in `models/transformer/`
**Testing**: pytest, ruff
**Target Platform**: Windows (local development)
**Project Type**: CLI + web-service (FastAPI)
**Performance Goals**: N/A (refactoring, no new perf requirements)
**Constraints**: Must not break prediction accuracy; same models, same features
**Scale/Scope**: ~20k converted card files in `./output/`
