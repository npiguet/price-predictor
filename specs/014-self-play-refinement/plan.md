# Implementation Plan: Self-Play Refinement

**Branch**: `014-self-play-refinement` | **Date**: 2026-04-20 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/014-self-play-refinement/spec.md`

## Summary

Add a self-play refinement loop to the sealed deck scorer pipeline. The loop generates pools from random sets, builds scorer-guided decks, runs self-play matches (scorer decks vs various opponents), and appends outcomes to the existing training file for retraining. Four CLI changes: `generate-pools` gains random set selection, a new `build-decks` subcommand builds scorer decks from pools, `match-outcomes` gains a `--generated-decks-path` flag for self-play mode, and `evaluate-scorer` defaults to random set selection. Implementation touches both Python (CLI, application, infrastructure layers) and Java (PoolMain, MatchWorkerMain, new SelfPlayMatchGenerator).

## Technical Context

**Language/Version**: Python 3.14+ (sealed module), Java 17+ (forge-connector)
**Primary Dependencies**: PyTorch (scorer model), Forge (booster generation, deck building, game simulation)
**Storage**: Flat text files (pools.txt, generated-decks.txt, match-outcomes.txt), PyTorch .pt checkpoints
**Testing**: pytest (Python unit tests), JUnit 5 (Java unit tests)
**Target Platform**: Windows 11 (development), any OS with Java 17+ and Python 3.14+
**Project Type**: CLI tool (two packages: `sealed` Python + `forge-connector` Java)
**Performance Goals**: Self-play match throughput comparable to Phase 0 (same order of magnitude in matches/hour)
**Constraints**: JVM memory ≤1200MB per worker; Forge AI games can crash the JVM (handled by crash recovery)
**Scale/Scope**: ~10,000 pools/decks per iteration; ~215 eligible sealed-legal sets
