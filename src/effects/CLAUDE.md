# `effects` — ability effect model

Entry point: `python -m effects <subcommand>` (see `src/effects/__main__.py` and `infrastructure/cli.py`). A pretrained model of **what each card ability does in play**, shipping two artifacts: a per-ability embedding cache (one fixed-width vector `e` per unique ability line, computed offline) and a state-conditional effect head that predicts an ability's effect on a given game state. `effects` **imports from** `sealed` and `price_predictor` (tokenizer, `tokenizer_store`, `build_vocabulary`, `forge_jvm`, `torch_checkpoint`, `torch_training.clip_per_group`, `append_only`, `ridge_probes`, `compute_basic_lands`, `ConvertedCardLocator`, `card_embedding_layout`, `embedding_store`); never the reverse, and never `sealed.application`. The boundary is asserted by `tests/unit/effects/test_import_boundaries.py`.

The design is staged: each stage widens the corpus without invalidating what came before. **Stage one needs no Forge patch at all** — it collects through the public event bus and a bracket around stack resolution — so the first embeddings and all three evaluation gates exist before any engine patch is written.

Subcommands:

- **`extract-keyword-definitions`** — spawns Java `KeywordDefinitionMain` to write keyword → reminder-text template for every Forge keyword to `--output` (default `output/effects/keyword-definitions.json`). The encoder expands an *unknown* keyword unconditionally, so this file is what makes a set the vocabulary predates readable rather than a bare `[UNK]`.
- **`build-vocab`** — wraps `price_predictor.application.build_vocabulary`, scanning **three** sources: converted cards, converted token scripts, and the keyword-definition file (expansion substitutes reminder text in, so unscanned reminder text would expand to `[UNK]`). Seeds `[PAD]`, `[UNK]`, `cardname`, `[MASK]`, `[CLS]` at low ids so `--target-size` (default 5000) cannot truncate them away. `--surface prose` (default) writes `models/effects/vocab.txt`; `--surface script` scans the sidecars' script lines and writes `models/effects/vocab-script.txt` — **a path of its own**, so a stage-four rebuild never overwrites the vocabulary a stage-one-to-three checkpoint recorded and can still load against.
- **`train-effect-model`** — trains both transformers jointly from random init. The split holds out cards by **newest first printing** until they cover ≥ 8% of `output/cardsfolder/`, then **excludes from training every game holding a record that names a held-out card** — records from one game share a board, so a held-out card in the context of a training record leaks through its context role even when it is not the acting ability. Game-disjoint validation takes 10% of what remains. The per-batch mixture is the eight-class one, renormalized over the classes present (a stage-one corpus has three of eight), and fields whose record kinds are absent contribute no loss. Within a class, records weight ∝ `effective_games^(−0.5)` capped at 20× the most-observed text's weight — **games, not records**, so one long game producing hundreds of records of one ability does not make it look well-observed. Best checkpoint by card-disjoint validation loss; `--patience` early stop. `--variant {full,identity,state-only,no-state,taxonomy}` trains the four evaluation baselines on the identical pipeline, and every variant run **must** pass `--split-from` (a baseline that saw different games is not a baseline). `--withhold-keyword` holds one implemented keyword's token out of training so the zero-shot check has something to measure. `--context-cache` is the documented 8 GB fallback: a stop-gradient momentum cache refreshed every `--cache-refresh` batches.
- **`encode-abilities`** — computes the cache once, offline; every downstream consumer reads it rather than the encoder. `--variant` resolves the **checkpoint and the output suffix together**, so a baseline is never encoded with another variant's weights and never lands on the shipping cache. The `taxonomy` variant has no encoder and emits a hash embedding of the sidecar's API type and parameter keys into the same row layout, so every `e`-geometry check reads one file shape. Idempotent; `--clean` removes only the files this variant wrote. The vocabulary and keyword-definition hashes are checked against the checkpoint before anything is written.
- **`collect-coverage`** (stage two) — sealed self-play only ever plays what sealed pools contain, so a card in no sealed-legal set never appears in a record at all. This builds decks over the **whole** converted corpus, weighted toward the cards with the fewest records, and plays rounds until every card is satisfied or retired. Three rules: the castability consult **only ranks** (never drops — being in a game is the precondition a stage-three intervention forks from, and a card the consult calls uncastable is exactly the one an intervention has to force into play); satisfaction counts acting hosts, event subjects and referenced refs but **not** mere snapshot presence (a card sitting on the battlefield while something else resolves teaches nothing about that card); and a card with no new qualifying record for `--no-progress-rounds` retires, which is the only thing that makes the run terminate. It reports **two residues** — cards judged uncastable, and castable cards short of `--target-records` — each retired card under its consult verdict; both fall to stage-three interventions. The coverage unit and the deck candidates come from `output/cardsfolder/` alone: a token script is not a deckable card and could never be satisfied or retired.
- **`collect-variants`** (stage four) — reads Forge's **source** scripts (not the converted ones), perturbs one parameter, and plays the result. A whitelisted numeric parameter shifts by up to ±3 or doubles, floored at zero; a selector swaps from a checked-in whitelist. Both whitelists exist because a shifted `CounterType` or a generated selector produces a script that fails to load rather than a card that plays differently. `--variant-volume` (default 0.2) caps variant records as a fraction of the real records already present, so the cap scales with the corpus. A variant of a held-out card is **held out with it**, exists on the script surface only, and is never converted to prose. A sidecar pass (`VariantSidecarMain`) runs before the first game: a variant without one produces records nothing can join, and the join is designed to fail loudly.
- **`evaluate-effect-model`** — the three gates and the reported checks. **Splits are never a flag**: the held-out card list and both `game_id` sets come from `--checkpoint`, because the corpus is append-only and a recomputed split would score the gates partly on games the model trained on. A `--variant-checkpoint NAME=PATH` recording a different split or different vocabulary hashes fails fast.

## Collection

Instrumentation is an opt-in on a command that already exists:

```bash
python -m sealed match-outcomes --effect-records output/effects/records/
```

`--effect-records` has **no default** there — collection is the opt-in, not the point, and a default would quietly turn every self-play run into a collection run. Absent the flag nothing changes: no shard is opened, and `match-outcomes.txt` and `cards-played.txt` keep their exact format and content. The instrumentation costs no extra simulation; it rides matches that were going to be played anyway.

Attribution mode is **detected at worker startup**, not compiled in: the patch lives in the sibling `../forge` checkout, which is rebuilt independently and re-patched by hand after every Forge upgrade, so a build-time switch would silently mislabel a corpus collected after the patch lapsed. Every record carries the detected `mode`.

`MatchWorkerMain` also has a **records-only mode**: with `-Deffect.records.dir` set and `-Doutput.file` absent, neither sealed writer is constructed at all. The coverage and variant collectors reuse this worker, and their decks are built for coverage rather than for a fair self-play sample — mixing them into the sealed corpus would corrupt the scorer's training data.

### The patch set

`forge-connector/patches/0001-Add-effect-record-instrumentation-hooks.patch` is a real `git am` patch against the sibling checkout, generated by `git format-patch` from its `effect-record-hooks` branch so a Forge upgrade is a rebase rather than a re-apply. It adds the trigger-handler cause channel and the missing `AbilityKey.Cause` at the `Destroyed` firing site, the shared replacement execution point, the threaded sub-ability pointer, and the trigger-fire and playability logging points. It also adds the mana-production point, static-keyed accessors over every type and colour layer table, the legal attacker and blocker sets the AI computes and discards, and the responsible-static lookups behind them.

Applied, a patched run reaches **all eight** sampling classes.

A `continuous` record's `types` and `colors` are each one flat token list, because the record schema fixes a contribution's six fields: a bare token is a type or colour the static adds, `-x` one it removes, and a lone `=` marks a line the static sets outright rather than adds to. Contract in `specs/023-ability-effect-model/contracts/record-schema.md`. Two consequences worth knowing. Subtypes and supertypes are recorded and then dropped at target derivation, because `types_gained` / `types_lost` cover the core types only — the record is the archive and a head reads a subset of it. And a `=` leaves `types_lost` unset rather than naming what it displaced: the snapshot beside the record is the board *after* the static applied, so reading the entity's types back would name what it still has.

Three collectors repeat themselves, and all three are capped **by identity rather than by count**: continuous effects reapply on every recompute, the AI re-asks who may block while it evaluates a combat, and a Mountain taps a dozen times for the same R. The repeats describe a board that did not move, so one carries the observation and the rest are duplication — legality records were four fifths of the corpus before coalescing, and mana fell from 33 a game to under 5. A count cap would keep the first N and then nothing, concentrating a card's records in whichever games came first; one per game spreads them across every game the card appeared in. `--mana-cap` is keyed on the mana produced as well as the ability, so a dual land records each colour it makes.

Mana is **reservoir-sampled** (Algorithm R) rather than taken first, and the reason is the whole point of the cap: a land's first tap is turn one against an empty board, so keeping it would make every mana record describe the same early game — a bias in the one input the model conditions on. The records are therefore held until `close()`, because which activation survives is not known until the game ends; a JVM that dies loses that game's reservoir, which is bounded by `--mana-cap` per ability and cheap against a crash that already cost the rest of the game. Two consequences worth knowing: the state snapshot is taken when the mana was made rather than at flush, and the expensive part is paid a logarithmic number of times rather than once per activation.

Both samplers scramble their seed through SplitMix64's finalizer first. Games are seeded consecutively, and a linear congruential generator's first output is nearly a linear function of its seed, so without it consecutive games take nearly the same first sampling decision — a correlation across the whole run that no test of one game can see.

The five cap flags (`--mana-cap`, `--playability-rate`, `--interventions-per-game`, `--probes-per-game`, `--probe-keywords`) are per-worker-process quantities the Python supervisor cannot observe, so they reach the JVM as `-Deffect.*` system properties and `CollectionCaps.fromSystemProperties()` reads them back, each falling back to its default rather than failing. `sealed` restates the defaults rather than importing them — it never imports `effects` — and `tests/unit/effects/domain/test_collection_caps.py` pins the two sides together.

Nothing here depends on the patch being applied: the connector builds against **stock** Forge, reaches every hook by name through `PatchHooks`, and falls back to bracket attribution when it finds none. The cost of the reflective approach is that a typo in a hook's name shows up at runtime as `degraded` rather than at compile time, which is why every record carries the detected mode and `tests/integration/test_effects_patched.py` asserts it. For the same reason the tests read the checkout rather than assuming it — one that pinned `degraded` would fail the day the patch landed, with nothing wrong.

### Forks (stage three)

Some abilities are never cast in any game Forge's AI plays — it judges them bad, cannot afford them, or never draws them into a board where they do anything — so no amount of observation produces a record. An **interventional resolution** forks the game and forces one, writing the effect half alone (there was no real activation, so there is no cost half to link to). A **damage-step probe** re-runs one combat with a keyword stripped; it carries `fork = true` and `interventional = false`, which distinguishes it from an intervention by flags alone, plus `mirror_of`.

Two choices in `intervene` are what make it produce anything. The ability goes **on the fork's stack directly** rather than through `ComputerUtil.handlePlayingSpellAbility`, because the cost is usually the reason the record is missing: routing through cost payment succeeds only on free plays, which is how a first attempt produced nothing but land drops. And the candidate is chosen at a **phase boundary**, not from the playability hook that knows exactly which candidates the AI declined — that hook fires inside the AI's own evaluation, and forking there copies a game mid-decision and re-enters the rules engine underneath it.

A probe forks at the **phase event**, which fires before the turn-based action that deals the damage — the only moment the copy can diverge from a board where nothing has been dealt yet. The keyword comes off through the layer system rather than the printed list, so a printed, equipped and until-end-of-turn keyword all go the way the rules would take them. The fork then runs `assignCombatDamage` and `dealAssignedDamage` itself.

The branch is **held rather than written**, because it mirrors the real combat record and that record has no id until the step the probe forked ahead of has finished; `BusBracketCollector.onCombatRecord` hands the id over when it writes one. Reconstructing the pairing from board state instead would break on two identical-looking combats in one turn.

A probe's payload names **both the keyword and the carrier** (`probed_keyword`, `probed_entity`). The keyword alone is ambiguous on a board with two tramplers, and an evaluator reproducing the perturbation model-side would strip the wrong creature — comparing against a counterfactual nobody ran. Both fields are absent on an observed combat record, which perturbs nothing.

Three rules the budgets depend on: every fork is score-checked against the live game **before** any perturbation (a copy that already disagrees is measuring the copier); a discarded fork **still counts against its budget** (otherwise a systematically failing copy retries until the game ends); and at most **two** forks may target one real resolution — a fixed constant no flag can raise. `--probe-keywords` is the runtime switch and is deliberately separate from the build decision gate 2 drives, so a checkout with the machinery takes no fork unless asked.

The real-versus-fork difference is computed at **evaluation time** and never becomes a training target: a model trained on its own disagreements would learn to reproduce its errors rather than correct them.

## The gates

| Gate | What it asks | Blocks? |
|---|---|---|
| **1** — identity baseline | Is the encoder reading text? All three margins must hold on the card-disjoint split's unique-text stratum — resolution records whose acting text appears on **no training card**, which is the only slice where a baseline holding a free vector per text cannot simply recall the answer. ≥ 0.05 absolute affected-gate F1 gain, ≥ 0.05 absolute zone-outcome accuracy gain, ≥ 5% relative Poisson-deviance reduction. Three margins because they fail differently — the gate F1 says whether the model knows *that* something happens, the zone accuracy *what*, the deviance *how much*. | **Yes** |
| **2** — damage-step keyword canary | Per keyword over the eight damage-step keywords: ≥ 200 qualifying records and ≥ 70% direction agreement under a **model-side** perturbation (remove the keyword from the ability token, or from the overlay's temporarily-granted channel where it is not printed). Under-sampled routes the same way as wrong — treating untested as passed is how a canary stops being one. | **No** — its per-keyword verdict is what decides whether stage three builds probe machinery at all |
| **3** — collapse canaries | Mean pairwise cosine ≤ 0.5 over 10,000 random pairs, top principal component ≤ 30% of variance, over one vector per unique ability text. Checked on the geometry rather than the loss, because a collapsed space passes every average-case metric. | **Yes** |

## File formats

**Effect-record shards** (`output/effects/records/{run_id}.{worker}.jsonl.gz`): one JSON record per line, append-only. A shard per worker rather than one shared file because records are far larger than a match-outcome row, so concurrent appends would interleave mid-record. Each file is a concatenation of complete gzip members, one per block of 256 records: every member stands alone, so a worker killed mid-write truncates the last and the reader stops there, which is the trailing-partial-line rule applied a block at a time. A game costs 4.3 MB of JSON and 80 KB gzipped, and the corpus is what fills the disk on an overnight run. Plain `*.jsonl` still reads — the corpus is append-only and older shards cannot be regenerated. `record_id` is `{run_id}.{worker}.{counter}` and `game_id` is `{run_id}.{worker}.{game counter}` — both carry the worker index because workers count independently, and `game_id` is the join key for a checkpoint's recorded split. The envelope is **frozen before stage-one collection**: later stages make new `kind` values reachable and add snapshot tiers, but never redefine a field. Four compatibility rules govern that and are enforced by `tests/unit/effects/domain/test_schema_compatibility.py` rather than by a version stamp. Full schema: `specs/023-ability-effect-model/contracts/record-schema.md`.

**Provenance sidecars** (`<name>.provenance.json`, beside each converted `.txt`): the join between runtime Forge trait objects and converted ability lines, written by `python -m price_predictor convert`. Converted-line ordinals cannot be the key — the converter runs one per-face bracket counter across five mixed line kinds, emits keyword-derived lines first though Forge appends them last, and merges and deduplicates relative to the runtime objects — so the key is printed provenance: `(script_file, face, trait_kind, index_within_kind)`, the script file including its tree. A rendered line merged from several traits carries **several** keys; a trait the converter deduplicated away maps to **no** line and is listed in `dropped_keys` (still live at runtime, so a record naming it is kept); a key in neither **fails loudly**, because that means a reconversion happened between collection and training. Row *i* of the ability cache is `lines[i]`. Full contract: `specs/023-ability-effect-model/contracts/provenance-sidecar.md`.

**Ability cache** (`output/effects/abilities/<tree>/…`): one `.npz` per source file holding a `float32` array of shape `(n_lines, e_dim)` under the key `e`, row-aligned with that source's sidecar. It lives **outside** `output/cardsfolder/` because the sealed pipeline's `encode-cards --clean` deletes every `.npz` under that tree. A variant writes `<name>.{variant}.npz` beside the shipping `<name>.npz` rather than over it.

**Keyword definitions** (`output/effects/keyword-definitions.json`): `{"<display name>": {"reminder_template", "generated_script"}}`, keyed by display name because that is what a card's keyword line and the converted text both spell. `generated_script` is captured at Forge's keyword factory — the traits it generates, rendered as script — and is null for the engine-coded minority, which generates none and keeps its template. On the script surface a keyword expands to that script; on the prose surface, to the reminder text.

**Variant scripts** (`output/effects/variant-scripts/`): perturbed Forge **source** scripts, flat, each filed under `sanitize_card_name(<variant name>).txt` — the filename **is** the path its provenance key resolves to, so it cannot be derived from the source file's own stem. Each gets a sidecar from `VariantSidecarMain`, which runs the ordinary converter with the text output suppressed: a key's `index_within_kind` is the trait's position in Forge's runtime trait list, so only the parser that builds that list can number it the way a record will. The tree is therefore the one whose sidecars sit beside a *source* script rather than a converted one, and it has **no prose surface at all** — `SidecarCache.prose_for` returns None for it, and the prose surface falls back to the script.

Loaded into a worker by staging them into Forge's custom-cards directory before `FModel.initialize` — the card database is read once at startup, and a script that appears afterwards is invisible for the life of the JVM. Staging also registers every name with `VariantRegistry`, which is what makes `ProvenanceKey` say `variant-scripts/`: once loaded, a variant is an ordinary non-token card and nothing on it says otherwise.

## One pipeline, two callers

`application/surface_batching.py` turns records into the trunk's keyword arguments, and both the trainer and gate 1's evaluator go through it. They have to agree exactly: when they did not — one keying the batch's encodings by prose, the other looking them up by script — the effect head trained on an all-zero `e`, every loss still fell, and the four evaluation baselines came out byte-identical to the shipping model. The encoding text therefore has **one** definition (`SurfaceBatcher.text_of`), and so do the variant masks, which are the whole difference between a baseline and the model gate 1 compares it against.

`infrastructure/model_runner.py` is the other half: it rebuilds encoder, model and batcher from a saved checkpoint. The `identity` baseline is the case that would break quietly — its `e` comes from a free embedding table rather than the encoder, so the table rides in the checkpoint's `extra` and a run that rebuilt it empty would score the baseline on random vectors and hand gate 1 a margin nobody earned.

## Performance invariants

Four things on the hot paths are load-bearing rather than incidental, and each has a failure mode that looks like a working run.

**`e` enters the head by row index, never by value.** A training surface's `Slot.e` is an `int` naming a row of the batch's encoded-ability matrix, and `scatter_e_rows` turns rows into vectors on the device in one gather. Reading the vectors back to the host per ability slot would both stall once per slot and **sever the gradient** — the effect head's loss reaches the ability encoder through this path and no other, so a model trained that way would optimize the head against a frozen random encoder and still report a falling loss.

**The loss decomposition is opt-in.** `per_entity_loss(..., report_parts=True)` reads each term back as a Python float, and each read synchronizes; with fifteen active fields that is fifteen stalls per batch for numbers the training loop discards. The epoch's running loss accumulates on the device and is read once when the epoch closes.

**`encode-abilities` batches by unique text.** The corpus repeats itself heavily — every *Flying*, every *deals 3 damage to any target* — so `AbilityEncoderRunner` deduplicates a card's lines before the forward pass and encodes 256 texts at a time. It loads the checkpoint once for the whole run and calls `eval()`, which matters beyond dropout: the encoder adds noise to `e` while training, and a cache built without it would differ between two runs of the same command.

**The trainer materializes the corpus.** `load_corpus` reads every shard into a list, because the split derivation and the weighted sampler both need the whole corpus indexed by game and by sampling class. Everything else streams (`read_records` is an iterator, `count_records` counts lines without parsing them). This is the known ceiling on corpus size and the thing to change first if a run runs out of host memory.

## Model artifacts

Checkpoints live under `models/effects/effect-model/` (`{timestamp}.pt` plus a rolling `latest.pt`); a variant writes to `models/effects/effect-model/{variant}/`, so a baseline run can never overwrite the checkpoint the cache was built from. Beyond weights, a checkpoint records **the split it trained against** (the held-out card list and both `game_id` sets, enumerated rather than derived), the vocabulary and keyword-definition paths and their content hashes, and the keyword withheld from training. Every inference command re-hashes what it actually loaded and fails fast on a mismatch: encoding a cache against a different vocabulary produces vectors that look fine and mean nothing. The MLM, script-API and pairing heads are training-only and are filtered out at save time.
