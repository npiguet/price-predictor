# Gen-3 model layout

Rules to respect when changing the input layout, the relation attention or an output head. This file does not describe the architecture:

- What the layout is: `specs/2026-10-30-ability-effect-model-gen3.md` § 9 (input), § 10 (relation-aware trunk), § 11 (outputs).
- Code: the input surface in `domain/input_vocabularies.py` (the name lists and id tables), `domain/input_layout.py` (slot kinds, `Slot`, the scalar encoding, the `[GLOBAL]`, `[ACT]` and `[PLAYER]` slots), `domain/card_features.py`, `domain/slot_lines.py`, `domain/slot_relations.py` and `domain/surface_builder.py`; then `domain/relation_attention.py`, `domain/relation_types.py`, `domain/effect_head_layout.py`.

## Orders are part of a checkpoint

- The order of every name list an input slot reads or an output head names columns by fixes rows and columns of the model's tables, a list derived from an enum or a dataclass's fields included. A checkpoint records a digest of each list in `domain/checkpoint_layout.LAYOUT_VOCABULARIES` and a loader refuses a difference, so reordering or inserting into any of them invalidates every existing checkpoint (`checkpoints.md`). A new list is registered there: `tests/unit/effects/domain/test_layout_vocabularies.py` fails on a public name list of the layout modules, or a head field's classes or members, that the registry lacks.
- Those lists are generated, not hand-edited:
  - `domain/kept_keyword_flags.py` by `scripts/scan_keyword_flags.py`; its test fails when the file is stale.
  - `domain/forge_vocabularies.py` by `scripts/scan_forge_vocabularies.py`.
  - `domain/output_vocabularies.py` by `scripts/scan_output_vocabularies.py --manifest`, from a built manifest. The lists checked in are provisional, surveyed from pilot collections (the module's docstring names them): before the first gen-3 training, regenerate them from the curated corpus's manifest, and update the head widths `tests/unit/effects/domain/test_layout_vocabularies.py` pins, which follow the lists' lengths. A checkpoint trained on the provisional lists loads against those lists only.

## Input slots

- `slot_lines` is the one list of a card's ability slots, read by both the batcher and the surface builder. `board_entities` is the one card list. The batcher reads each record's board once (`RecordBoard`: each card with its `slot_lines`, the command-zone cards after the board's) in its text pass and hands it to `SurfaceBuilder.build`, so neither `slot_lines` nor `command_zone_entities` runs twice for a record.
- A library card below its library's top gets no slot, and `derive_targets` writes it no target (`has_card_slot`; only order rank 0 is the top). The snapshot holds such a card only because the record's own events draw, mill or search for it, so its slot would hand the head the outcome. Its player's counts and library events keep what happened to it.
- A keyword keeps a card-level flag only where a Forge card-script selector or engine check names it. A keyword on a printed keyword line is also read through that line's reminder text, which training expands with a probability and inference expands only for an unknown keyword (`INFERENCE_KEYWORD_EXPAND_P = 0`, `text-encoding.md` § Tokenization). A keyword a static grants takes the granting static's line and never reads its own reminder text. A line with no key reads through `keyword-line/<fragment>`.
- A continuous record's keyword flags read its board as written, with no mask of the record's own keywords. The collector already writes that board without the record's static, so a keyword left on it comes from another source; hiding it again clears a flag the creature holds on a creature the record's `keywords_gained` names, which hands the head the answer.
- A face that is not up gives inactive slots.
- A combat record's card slots read nothing of its damage assignment (`payload.assignment_choices`). The assignment says which creatures deal damage in the step, so it would show a first-strike step's first strikers without the keyword, and gate 2's stripped twin would keep it. Who attacks and who blocks is the card's combat status and its `attacks` and `blocks` relations; the combat grid (`grid_edits.grid_records`) edits no assignment.
- A card slot reads its entity's `role` one-hot over `input_vocabularies.ENTITY_ROLES` (`tier`, then `state_snapshot.EntityRole`'s members). A last-known copy keeps the zone it last had, so without it an `L<id>` copy with zone `battlefield` reads as a permanent. `EntityState.on_battlefield` is false for a last-known copy, and summoning sickness reads on `on_battlefield` cards only: Forge writes it in every zone, where it says "is a creature card".
- A last-known copy and its own card (`L<id>` and `E<id>`) get no `has_the_same_name` relation; their link is `last_known_state_of`.
- Two cards get `has_the_same_name` only when each is on the battlefield, on the stack or in a hand (`slot_relations.SAME_NAME_ZONES`, read from `EntityState.zone`, the zone the card slot's one-hot reads; a last-known copy counts by the zone it last had, a face-down card has no name and relates to none). A card that chose a name (Pithing Needle, Cranial Extraction) keeps its link to every card of that name in any zone, since the chooser's rule can reach a library or graveyard card. Without the limit the pairs grow with the square of the copies of a basic land in the graveyards, libraries and exile, which were 16% of the fixture's relation triples, and relate cards no effect acts through.
- On an effect half the acting source's `costs_paid` block is all zero (`card_features._paid_for`). A forced resolution skips the payment, so "paid no mana" would tell a forced half from a live one.
- `tests/unit/effects/domain/test_layout_vocabularies.py` pins the card slot's width and its parts in order (`card_features._CARD_PARTS`). Adding, removing or widening a part changes the width every checkpoint's input projection was built for.
- A card part reads the card through its `card_features.CardContext` alone (the entity, the record's snapshot, acting player and payload, gate 2's masked keywords), built once per slot. A part that needs more of the record widens the context, so every part's inputs are declared in one place.
- Each slot kind's width is a constant of the layout, computed once per process by `domain/slot_widths.layout_widths` from a blank record, player and card run through the slot builders, and never measured on records. A training run's trunk and a saved model's batcher (`SurfaceSpec.for_training`, `SurfaceSpec.for_saved_model`) both read it. A builder whose width depends on what a record holds breaks every batch that record is in; `test_layout_vocabularies.py` holds every fixture record's slots at the layout's widths.
- The input reads targets as cast (`Refs.as_cast`: `targets_at_cast`, else `targets`) for `[ACT]`'s target count, every "targeted" bit and `[ACT]`'s `targets` relations. Reading `targets` on an effect half would hand the model the fizzle it is to predict. On a record without `targets_at_cast` the fallback still leaks it. A target `refs.targets_on_stack` names is a spell or an ability, by its card: the acting item's `targets` link ends at the card for a spell, at a line for an ability (`StateSnapshot.targets_card`). A permanent whose ability is the target gets no targeted bit and no `[ACT]` `targets` relation; a spell that has left the stack since keeps both. The input reads an entity's `stack_extras` as written; on an effect half the acting item's entity carries them as cast (`record-format.md`). Records collected before 2026-11-18 hold them after the check and leak the fizzle through them.
- A keyword reads in one spelling, defined in `domain/keyword_names.py` (`Ward:2` → `ward`, `Protection:Goblin` → `protection_from_goblin`, `Trample:Planeswalker` → `trample_over_planeswalkers`, which is trample too).
- Floating effects and delayed triggers with no entity in the snapshot are card slots after the board's. They are no per-entity target.
- The pending event reads on three slots: its type, amount, mode (`input_vocabularies.PENDING_EVENT_MODES`, 180 names generated by `scripts/scan_forge_vocabularies.py` from Forge's `TriggerType` and `ReplacementType` enums, the two a record's `mode` is named from, so no mode a hook can name lands in "other"; `test_scan_forge_vocabularies.py` fails when the list differs from a fresh scan) and combat bit and from- and to-zone (one-hot over `ZONES`) on `[GLOBAL]`; on the card slot whether the card is its subject, its `source`, its `defender`, among its `blockers` and its `cause`; on the player slot whether the player is its subject, its defender and its cause. `cause` is a ref (`E74`, `P1`), not a vocabulary, so it is a bit like the source. A trigger's fired bit turns on all of them, and a player subject reaches no card slot. Both the card the event names (`E<id>`) and its last-known copy (`L<id>`, by `last_known_state_of`) carry the subject bit (`StateSnapshot.names_as_pending_subject`): the event names the card as the game holds it now, and happened to the object the copy shows. The `[GLOBAL]` and player widths are pinned in `test_layout_vocabularies.py` beside the card slot's.
- A card slot's `hidden_keywords` part is three bits, can't block, can't attack and must be blocked (`card_features.CANT_BLOCK_KEYWORDS`, `CANT_ATTACK_KEYWORDS`, `MUST_BE_BLOCKED_KEYWORDS`: the two lure spellings, `All creatures able to block CARDNAME do so.` and `CARDNAME must be blocked if able.`, one bit), read from `granted_temporary.hidden_keywords` in Forge's own spelling. No line and no keyword flag carries a hidden keyword, and the blocker and attacker legality outputs turn on the first two and the blockers' `combat_requirement` on the third. A conditional spelling (`CARDNAME can only attack alone.`) and every other hidden keyword set neither.
- A face-down card's `real_face` reads in the card slot's `real_face` part (types, colours, mana value, printed power and toughness, the number of subtypes); zeros on any other card. Its subtypes are the slot's `real_face_subtypes`, a third id list over the subtype table beside `subtypes` and `chosen_types` (`card_features.real_face_subtype_rows`, `TrunkInputs.real_face_subtype_ids`); the model adds one learned vector, `real_face_subtype_offset`, to each of those rows before the sum, so a real-face subtype and an own subtype of one name are two inputs, and a card's own subtypes (a face-down Toy's `toy`) are unchanged. A checkpoint saved without that vector is refused at load. Its lines stay inactive ability slots.
- A rewrite record's incoming event is its pending event: the collector writes `state.pending_event` equal to `payload.incoming`, and the input reads the former. Its `outgoing`, `result`, `replaced_by` and `buffered*` are outputs no slot reads.
- A dungeon is a card slot whose one keyword line, under the dungeon keyword's bare key, reads as one slot per room line (`board_keys`), as a saga's keyword line reads as its chapters. The room slot named as the player's room (`global.dungeons[].room`) is active and every other room slot inactive (`SurfaceBuilder._slot_lines`); a room line names its room through `LineLookup.room_of`, the room trigger's `ValidRoom$` (`SidecarLine.room`). Every `LineLookup` implements `room_of`: a lookup without it fails on the first record holding a dungeon.

## Relations

- `relation_types.FAMILIES` is the connector's `LinkFamily` list in the same order, pinned on both sides (`test_relation_types.py`, `LinkFamilyContractTest`). A family appears in both at once, so a fact the reader alone derives about one slot and `[ACT]` is a slot feature, as the pending event's subject and source are.
- `RelationEncoderLayer` keeps `nn.TransformerEncoderLayer`'s parameter names.
- The relation key and value tables start at zero and sit in the `head` parameter group.
- A record's relation triples are built once the slots are fixed, after context dropout and gate 2's strip. A line end with no slot reads its card's; a link to an object with no slot is dropped.
- `scripts/measure_trunk_step.py` measures a step on a curated shard.

## Outputs

- A field takes a silent value only where the collector writes its event for every occurrence.
- A written value outside a field's scope is refused (`FieldScope.admits`, `FieldSpec.supervised_value`): a player takes no `damage_taken` (its `life_delta` and `poison_delta` carry the damage), and a permanent takes no player field. The legality fields, which a payload's marks set on a card or a player alike, admit both.
- A cost half takes no silent value (`FieldSpec.silent_by`, every supervising class but `resolution-cost`): it names what its payment did and nothing else. It supervises `zone_outcome`, `tap_state`, the counter fields and `life_delta` (`supervised_by`), and only where its `costs` write them (`training.md` § Losses).
- `paired`, `merged`, `class_levels_gained`, `gained_city_blessing` and `completed_dungeon` take their silent 0 on a resolution's effect half alone (`supervised_by` in `effect_head_layout.PER_ENTITY_FIELDS`): the first three come only from their own APIs' clause rules, the last two from `BusEventReader`'s command-zone reading. Without it the head sees only 1s and learns a constant.
- `abilities_gained` and `abilities_lost` take their silent 0 on a continuous record alone: a contribution's `abilities` names every line its static grants and, with a `-`, every one it takes (`continuous_lines.abilities_changed`: a count, and whether any went). A resolution's silence says nothing, since an `Animate` of its own source names no subject.
- `door_unlocked`, `entered_in_combat` and `became_blocked` have no silent value: a Room spell's entry unlocks a door with no `UnlockDoor` clause, and Forge adds combatants and blocks attackers through APIs no clause rule reads.
- A continuous record's lost fields are read off its board, which is the board without the static (`continuous_lines.line_changes`). A lone `=` in `keywords`, `types` or `colors`, and a whole-class token (`-all-card-types`, `-all-creature-types`, `-all-land-types`, `-all-artifact-types` and the rest of Forge's `RemoveType`), displace what the entity held on that line, or that class of it: that is lost, less what the static gives back, and on such a line what the static gives that the entity held is no gain. A card type lost takes its subtypes (205.3d), by `forge_vocabularies.SUBTYPE_SECTIONS`. `all-creature-types` marks `subtypes_gained` unknown, since no column states every creature type. A contribution's `hidden_keywords` name no output column and are not read.
- `library_events.tutor` is a `card_looked_at` whose `mode` is `SearchedLibrary`, and nothing inferred from a shuffle (`effect_targets._RecordPass._library_events`): a mill, a draw or an exile from the top shuffles too. Every search of a library writes it, including one whose chooser is not the library's owner (Thada Adel's, `UncountedSearches`), whose event names the library's owner; a record collected before that change reads `shuffle` only.
- `pt_duration` is unknown on an entity whose `pt_change` events last for different times, since its deltas are summed over them (`mixed_pt_durations`); `type_color_duration` likewise, over the entity's `type_change` and `color_change` events together, since one field labels both (`mixed_type_color_durations`, `domain/lasting_change_labels.py`). `keywords_gained` and `keywords_lost` both stay 0 on `enchant` where one entity gains one enchant restriction and loses another (Animate Dead): both spellings fold to one column (`cancel_enchant_swaps`, the same file).
- `turn_structure_change` counts an event's `count` once for each player the event names (`aux_head_targets._turn_structure_count`). `effects_created` and the effect group count `continuous_effect_created` and `delayed_trigger_created` events, one per effect card the clause moved into the command zone.
- Every `zone_outcome` class and every created-objects group kind has a writer: an emblem is a `continuous_effect_created` (the effect kind), and a transforming card is a `face_change` (`face_changed`). A column nothing writes is deleted, since a class that is always 0 only costs width.
- `protector_changed` has no source, since Forge publishes nothing for it, so it never trains.
- The head has no output for the game's end: `build-corpus` refuses every record holding it (`corpus-building.md` § Curation), so no kept record could set one, and a `player_lost`, `player_won` or `game_drawn` event derives no target.
