# Building the curated corpus

Covers `build-corpus`, `holdout-cards`, the holdout rule and curation. Read on demand: `src/effects/CLAUDE.md` says when, and lists the other topic files in this directory.

## `build-corpus`

- **`build-corpus`** — reads the raw shard corpus under `--records-dir` once and writes a fixed dataset under `--output` (default `output/effects/corpus/`): `training/`, `validation/card-disjoint/`, `validation/game-disjoint/` — each an ordinary shard directory, so every existing reader loads it unchanged — and `manifest.json`. `train-effect-model --corpus DIR` reads the dataset instead of the raw corpus, so two runs differing only in hyperparameters read the same records in the same order; `--corpus` is the trainer's only input and the two holdout flags are no longer flags of its own, since the manifest already records the decision they would have named. Training records are selected per record; both validation strata are selected per **game**, the unit the split is decided in, so the card-disjoint cap admits or declines a whole game rather than trimming records inside one. No evaluator resolves a probe's `mirror_of` within a stratum. The split is the trainer's own rule under `--holdout-permille`/`--holdout-max-carriers`/`--holdout-unit`, over the card tree and the token tree alike: a token script printing a held-out text is a carrier, its script file is held out like a card, and a game holding it is held out. A game with a record naming a held-out card or token script goes to the card-disjoint stratum, a game whose `crc32(game_id) mod 10⁶ / 10⁶` falls below `--game-disjoint-share` (default 0.01; `--game-disjoint-keyword-share`, default 0.15, for a game holding a qualifying combat for a keyword in `--game-disjoint-keywords`) goes to the game-disjoint stratum, and the rest are training candidates. That draw is where placement starts, not where it ends. Placement (`domain/stratum_placement.py`, `place_games`) runs once over the whole corpus after the survey, from per-game inventories of rule-test-eligible records: the game-disjoint stratum takes only games two Forge AIs played, and the card-disjoint stratum every game naming a held-out card, random-seat games included (a random-seat game naming none trains); games of a candidate pool (draw below ten times `--game-disjoint-share`) carrying a (rule, polarity) short of its rule-test records are promoted to the game-disjoint stratum, smallest `crc32` first, and the stratum is topped up to two halves of at least 300 games; held-out games carrying a short (rule, polarity) are admitted first under the card-disjoint cap; and each validation stratum is split by game into a `selection` and a `reporting` half, balancing every (rule, polarity) count. Placement therefore depends on every game, not on the game alone: a rebuild over a grown corpus can move a game it placed before, and only the split a checkpoint records says where each game went. A record of a training game that acts through a held-out text — a token or a variant script printing it, or its template under `--holdout-unit template` — is not trained on: both passes route it away and the manifest counts it under the `dropped-held-out-text` stratum, while the rest of its game still trains. Training records are selected per class by copy counts (§ Curation): within a cell a text supplies at most `min(--reuse-cap × n, --text-cap)` written records, repeats included — and the card-disjoint stratum separately holds at most `--card-disjoint-text-cap` (default 50) **games** per held-out text. A game counts toward a held-out text only through a **resolution** record acting through it, the only kind gate 1 scores; a held-out game is admitted only while every held-out text it resolves is under the cap, and one resolving no held-out text is dropped rather than trained on — so every held-out text weighs comparably in gate 1's averages and in best-checkpoint selection. `--class-mix` sets the on-disk proportions over the eight sampling classes (default: the training mixture); a class the raw corpus cannot supply at its share is written in full with the shortfall recorded rather than silently under-filled — availability counts the records of training games only, under the per-text cap, and the manifest records each class's target (`class_targets`) and the proportions delivered beside the ones requested, the run warning on a class delivered short of its target — and `--training-records` (default 0, no ceiling) subsamples the capped result within each class to a total. `--variant-scripts` names the perturbed-script tree: a variant line's provenance names that tree, so without the root it resolves to no ability text, and a resolution record acting through it is refused as `no-acting-text`. `--vocab-path` decides the encoding surface the manifest's rarity table keys its texts on — built on the other surface, the table would key every text differently while looking exactly as valid, which is why `train-effect-model --corpus` refuses a `--vocab-path` on the other one. A build that would produce a dataset gate 1 cannot be scored on writes nothing and exits non-zero: an empty holdout, refused before the survey, or an empty card-disjoint stratum, refused after it. Two passes: a parallel survey (`--workers`, default CPU count) reads every shard once keyed by provenance key rather than by ability text — resolving a key to its text needs a `SidecarCache` over tens of thousands of files, and building one per worker would cost more than the scan — then one process folds every key to its text, computes the rarity table and the per-text/per-class thresholds, and a second parallel pass re-reads each shard and writes the three outputs under them. The survey tags every record with the catalogue's detectors (`tag_record`, as `rule-counts` does) and splits each game at the end of its shard (a raw shard is one JVM lifetime, which no game outlives) by what placement can still do with it: a game outside the candidate pool, or a random-seat game naming no held-out card, trains whatever placement decides and folds into the training supply there; a candidate game — a Forge-AI game of the pool, or any game naming a held-out card, random seat or not — keeps its records and its rule inventory until placement, after which a candidate it trained folds in. The write pass applies the game sets placement built rather than deciding again. Only training games' records size the class, family and text quotas and the copy plans, so the plan never counts a record the write pass routes away; the rarity table, the legality mode counts, the rule counts, the condition counts, the closed subtype and keyword lists (`closed_lists.subtypes_named`/`keywords_named`: what effects grant, remove or give a created object) and the held-out texts' game counts stay whole-corpus. **Gen-3 curation** (FR-054–FR-060a): a records set holding any shard but gen-3 exits 1 before a record is read; `rules/scenarios/` and `rules/heads/` are read once (`RuleCatalogue`, a `rules_dir` config field with no flag), and the manifest's `rule_map` snapshots every tagged or drawn rule's verdict and outputs with the map's digest, beside `effective_outputs`: of each rule's map outputs, those at least one of its tagged records carries (`domain/rule_output_carriage.py`: a per-entity output supervised at an outcome entity of the tag, the gate on a record that trains it, a verdict, global or created-objects output the record supervises; the survey counts them per rule and output), which is all the rule mask and the rule tests read. After gen-2's natural share (`plan_selection`), `domain/rule_budgets.py` adds copies per class to the rules the map marks `trained` — the training stratum's over its natural shares, each validation stratum's over its own natural copies (FR-068a). A validation stratum is written in the training stratum's `--class-mix` (FR-059a, `corpus_curation.validation_multipliers`): no record is dropped, the class most over its share is written once a record, each other class repeats toward its share at most `--reuse-cap` times a record (`natural_copies` draws the fractional part from the record hash), and a class the mix omits is written once — and the write pass writes every copy with a `curation` member (`natural_share`, `copies`, `drawn_rule`, `drawn_rules`, `condition_entities`, `outcome_entities`; an added copy carries its drawn rule and that rule's tag entities in both roles, a natural copy none). A record a rare protection quality can be copied onto (`domain/protection_copies.py`) enters the budgets a second time, under its protection hash, natural share zero, and each protection copy drawn is written as a synthetic record `<record_id>~pc<i>`. Gate one takes a card-disjoint record's natural copy alone. `turn_action` records are written to no stratum and counted by subkind (`turn_action_left_out`); a permanent spell's resolution, acting through the implicit cast spell no line carries (`record_quality.is_permanent_spell`), is kept, keyed to the permanent's card by that key; a decision whose candidate key is unjoinable is refused as `unjoinable-key`. Once the corpus and its manifest are written, the build exits 1, naming each stratum and half, when a half's rule-test component already misses its precision target (`stratum_placement.rule_test_misses`: a rule enters at a Hanley–McNeil standard error of 0.1 or less, the component needs 0.05 or less, its standard error being √(Σ SEᵢ²) / m over the m rules that enter, so a half where a few dozen frequent rules enter passes even on a pilot's few dozen games; the 300 games a half needs is the selection-set freeze's exit, not this one) — the corpus is still read after an exit 1; the thresholds of research E5 (`min_games_per_half`, `max_item_error`, `max_component_error`) are config fields with no flag, so a test can lower them. Only the rule tests are judged here: the probes, grids and explained deviance wait for the selection set's freeze. Each family row in the manifest carries its `planned` count beside `share` and `written`. The written strata are then repacked: whole games are dealt to about `ceil(records / --shard-records)` shards by a hash of `game_id` seeded by `--seed`, and each shard is shuffled under `--seed` before it is written, so a shard mixes games from across the stratum and a record's copies are spread through it; the trainer still draws whole shards. A failed build leaves no stale manifest: `manifest.json` is moved to `manifest.previous.json` before the strata are cleared, and the new one is written atomically, last. The dataset is a pure function of the raw corpus, the flags and `--seed`, all recorded in the manifest alongside the source shard names and byte sizes, per-class and per-stratum record counts, and the unique-ability-text count of each output — the count that says whether curation preserved the tail, since no record count can. A grown raw corpus is rebuilt whole rather than extended in place, because the split and the rarity table are both corpus-wide quantities — the three output directories are cleared before the write pass, so no shard of an earlier build survives into a dataset the manifest does not describe; `--verify` reports the manifest's drift against the corpus on disk (shards added, removed, resized) and writes nothing. A checkpoint trained with `--corpus` pins the manifest's digest alongside its split (`checkpoints.md`); `evaluate-effect-model` fails fast when the dataset it reads has been rebuilt since. The manifest still carries `token_keys_remapped`, `token_keys_ambiguous` and `forge_tokenscripts` from a since-removed token-key remap; a build writes them as `0`, `{}` and `""`, and they stay because every manifest on disk holds them and its digest is pinned by the checkpoints trained on it.

## `holdout-cards`

- **`holdout-cards`** — writes the depletion list `sealed generate-pools --exclude-cards` reads: one Forge canonical card name per line, every card carrying a held-out ability text; a split card under its combined name ("Fire // Ice"), the one Forge's exact-name depletion compares, which the collectors' `read_name_list` reads back as the converted first face too. The one coupling between the two packages, and deliberately a plain file rather than an import — `sealed` must never depend on `effects`. It selects texts through the trainer's own rule, so the two cannot disagree; the same `--holdout-permille` and `--holdout-max-carriers` must be passed here and at training, because a depleted corpus was composed against them and a checkpoint records them.

## Holdout

**Holdout.** `--holdout-unit template` (the default on `holdout-cards` and `build-corpus`; `train-effect-model` takes the manifest's) holds out masked templates: the chained text with every digit run outside chain labels, `CARDNAME` and description values masked, so `NumDmg$ 2` and `NumDmg$ 3` fall on one side. `text` reproduces feature 023. Token scripts count as carriers, toward `--holdout-max-carriers` too, and a token script printing a held-out text is held out by its script file, so a game holding that token is held out; `holdout-cards`, `build-corpus` and the trainer's recompute all read the token tree for it. `HeldOutCards.holds_text` tests any script text against the held-out units, a template under `--holdout-unit template`, which is what lets `collect-variants` and `build-corpus` refuse a variant or token printing one. The trainer recomputes the holdout over its `--cards-folder` sidecars and refuses a disagreement with the manifest. `collect-coverage --only-cards <holdout list>` builds decks from those cards alone, under the run's own caps (the three decision-sampling rates included, FR-059a), and counts random-seat games too, since they go to the card-disjoint stratum, and counts distinct games per text until `--min-text-games` (default 5). A game counts toward the text `build-corpus` credits it to — its first acting key whose text `holds_text`, through the one `HeldOutCards.text_acted_through` both commands call — so under `template` a game whose first acting key prints a held-out template no listed card carries counts toward no listed text at all; the round therefore takes the three holdout flags with `build-corpus`'s defaults, and has to be passed the same values.

## Curation

**Curation.** Every record has one effect family (`domain/effect_families.py`): the acting line's API type for resolutions, the trigger's `Mode$`, the static's `Mode$`, the replacement's `Event$`, the damage-step keyword set for combat, the restricting static's mode or first failing verdict bit for a decision, the rarest single restricting mode for a legality record (a `Mode$` list counts as each mode; the survey's per-mode counts go in the manifest as `legality_mode_counts`, and the trainer and evaluator place legality records by the same table), and a keyword line's display name whatever the kind. Each class budget is split equally over families, then (for effects, rewrites, combat and continuous) over outcome signatures, the set of distinct (zone outcome, changed) pairs. One water-filling allocator (`domain/budget_allocation.py`) does every split: a short family's records repeat up to `--reuse-cap` (default 4) and its unused share passes on. Real legality decisions fill up to half the legality class first. Each record is written `copies` times, every choice a function of its hash and `--seed`. The manifest reports per-family shares, repeats and shortfalls, records per signature, on/off-policy and real/what-if counts, keyword-threshold games and held-out texts with too few games. Each new manifest field is omitted at its gen-1 value, so a gen-1 manifest's digest is unchanged.
