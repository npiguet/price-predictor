fix(connector): build the castability consult's card with a real id

CardFactory.getCard(paper, null, null) derives the card id from the owner
and passes -1 for a null one, and readCardFace reads none of a script's
traits for a negative id ("for view purposes only"): no keywords, no
triggers and no A: lines, which is where an instant's or sorcery's spell
lives. The only spells left were the ones CardState synthesises from the
type line, so the verdict degenerated to "permanent => castable" and every
instant and sorcery in the game was under-weighted 4x for no reason.

Build the card through the four-argument overload with an explicit id
against a player-less dummy Game, the recipe RulesParser already uses for
convert (with no game at all, three cards' ability setup throws). Over all
33,232 unique cards this flips exactly the 7,296 instants and sorceries
plus 8 Adventure, Morph and Disguise lands to castable, nothing the other
way, and adds about three seconds to Forge start-up.

Pin the verdicts in an integration test (instant, sorcery, a Haunt spell
with no A:SP$ line, creature, noncreature permanent, lands, an unknown
name omitted, one verdict per recognised name) and the JSON shape the
Python connector reads in a Forge-free one.
