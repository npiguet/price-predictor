# Forge engine patches

`0001-Add-effect-record-instrumentation-hooks.patch` is applied to the **sibling `../forge`
checkout**, not to anything in this repository. It adds the hooks the effect-record collectors need
for exact attribution; without it the collectors still run, fall back to bracket attribution, and
stamp every record `"mode": "degraded"`.

**It must be re-applied after every Forge upgrade.** Forge is rebuilt independently of this repo and
an upgrade reverts it, which is why attribution mode is detected at worker startup rather than being
a build flag: a lapsed patch mislabels a corpus otherwise.

Nothing in this repository depends on the patch being applied. The connector builds against **stock**
Forge, reaches every hook reflectively, and falls back to bracket attribution when it finds none — so
an unpatched checkout collects a `degraded` corpus rather than failing.

## Applying

```bash
cd ../forge
git checkout -b effect-record-hooks
git am ../price-predictor/forge-connector/patches/0*.patch
mvn -pl forge-core,forge-game,forge-ai -am install -DskipTests
```

Apply the **whole series**, in order. Each hook is its own commit so it can be reviewed on its own,
and a partly-applied series is the state the collectors are built to detect rather than fail on: a
missing hook degrades its channel, and `PatchedCollectors` skips the `continuous` kind outright when
the three `…Without` methods are absent.

Then rebuild the connector, because the worker links against the freshly installed Forge jars:

```bash
cd ../price-predictor/forge-connector && mvn package -DskipTests
```

The series is generated by `git format-patch` from that branch, so `git am` replays it as commits and
a later Forge upgrade is a rebase rather than a re-apply. **A new hook is a new commit, never an
amendment of an existing one** — that is what keeps the series reviewable. Regenerate after adding
one, replacing the whole directory so a removed commit does not leave its file behind:

```bash
cd ../forge
rm ../price-predictor/forge-connector/patches/0*.patch
git format-patch <upstream>..HEAD -o ../price-predictor/forge-connector/patches
```

## Verifying

```bash
python -m pytest tests/integration/test_effects_patched.py -m integration
```

Three tests, and they read the environment rather than assuming it: on a stock checkout they skip, on
a patched one they assert the mode is `patched`, that a run reaches the unlocked record kinds, and
that snapshots carry tier 3. A short collection is the other check — records carry `"mode": "patched"`
and the worker prints the detected mode at startup.

## What each hook is for

| File | Hook | Unlocks |
|---|---|---|
| `TriggerHandler` | per-thread pointer to the running trigger (`get`/`setEffectRecordCause`) | cause attribution; **this is the hook mode detection probes for** |
| `TriggerHandler` | listener at the condition evaluation (`setEffectRecordTriggerListener`) | `trigger` records, fired and not |
| `ReplacementHandler` | listener around `executeReplacement` (`setEffectRecordListener`) | `rewrite` records |
| `AbilityUtils` | per-thread pointer to the resolving sub-ability (`getEffectRecordSubAbility`) | per-clause attribution |
| `AiController` | rules-level candidate verdicts (`setEffectRecordPlayabilityListener`) | `playability` records |
| `AiController` | legal attacker and blocker sets (`setEffectRecordCombatListener`) | the `playability` record's `attackers` and `blockers` subkinds |
| `StaticAbilityCantAttackBlock` | `cantAttackStatic` / `cantBlockByStatic` return the responsible static rather than a boolean | each forbidden creature's `responsible_static` |
| `AbilityManaPart` | listener where produced mana reaches the pool (`setEffectRecordManaListener`) | mana records, and with them the role-polarity probe |
| `Card` | static-keyed accessors over every type and colour layer table, and a public `CardColor` | the `continuous` record's type and colour channels |
| `Card` | `getTypeWithout` / `getColorWithout` / `getKeywordsWithout` — the layers recombined with one static's entries dropped | a `continuous` record's snapshot, which must not contain the effect it labels |
| `Combat` | `getAssignedDamage` — the damage assignment, which the engine spends and discards | a `combat` record's `assignment_choices`: what trample and deathtouch actually decide |
| `GameAction.destroy` | `AbilityKey.Cause` in the `Destroyed` run parameters | a destroy record can name what destroyed the permanent |

The hook names are a contract with `PatchHooks` and `PatchedCollectors`, which look them up by string.
Renaming one on either side degrades the corpus silently rather than failing the build — that is the
cost of building against stock Forge, and why the integration test asserts the mode.

## Not hooked, on purpose

A patched run reaches all eight sampling classes, both stage-three fork kinds work, and every
record field the schema names is written except two.

A `continuous` contribution's `name` stays empty. Eight cards in all of Forge write the name layer
from a static — six with `SetName`, Spy Kit with `AddNames`, Volrath's Shapeshifter with
`GainTextOf` — the head has no field for a name, and a name is open-vocabulary over 33,680 strings
unlike every other channel. `changedCardNames` is keyed the same way the other layer tables are, so
adding it later is the same shape of change as the type and colour accessors.

A `playability`/`decision` candidate's `responsible_static` stays empty. It would need a
`cantBeCastStatic` equivalent to the `cantAttackStatic` and `cantBlockByStatic` in this patch, and
even where that hook exists only about a quarter of forbidden creatures find a static: the rest are
stopped by the rules themselves — tapped, summoning sick, "can't attack" printed on the card — where
an empty list is the right answer rather than a gap.

Both are listed in `KNOWN_CONSTANT_FIELDS`, so `python -m effects field-coverage` names them as
expected rather than as findings.

The three `…Without` hooks arrived after the rest, so a checkout carrying an older revision of this
patch reports `patched` and still cannot suppress. `PatchedCollectors` checks for them by name and
collects no `continuous` records when they are missing, because a snapshot that still contains the
effect it labels is worse than no record.
